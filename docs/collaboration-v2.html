No second task system. Goals, work records, review subscriptions and continuation remain with the agents and their native clients. The bridge has no hidden workflow engine or scheduler.

The entire model-facing interface

Six methods are enough.

bridge_connect

Connect to a session using its native ID.

Connect is silent. A pending Codex target binds when it reads the first eligible message.
bridge_sessions_list

See connected sessions, receiver availability and what each last reported doing.

Read only. No transcript scan, enrollment or wake.
bridge_status_update

Publish your own short “working on” statement.

Timestamped and attributed. A silent metadata update.
bridge_message_send

Send a bounded request, informational message or reply.

One explicit recipient. Existing duplicate-send protection stays.
bridge_messages_read

Read incoming messages or inspect a selected exchange.

Receipt tokens stay inside the implementation; receipt is not task acceptance.
bridge_disconnect

Disconnect from one selected session.

Other connections remain. Native sessions keep running.

The default MCP catalog now exposes these six methods. The old ten-tool catalog is available only through explicit migration mode. Reload or install the updated plugin to use the new interface. Read the small method contract.

“Notified” means stdout completed, not that Claude read the message. Codex uses its native queue and reports submission separately. A replacement receiver may repeat an unread notification; existing receipts and idempotency protect against treating it as new work.

Restart the receiver, keep the session.

Native identity, connections and messages survive receiver shutdown. A short ownership lease expires after a crash; explicit activation starts the replacement. Opening a fresh terminal or listing sessions stays dormant.

Keep the original receipt.

A long review can reply after the old 30-minute receipt cutoff. The original message deadline still applies (one hour by default), as do cancellation, disconnection and the one-result rule.

Continuity without a bridge scheduler. The agent resumes its original task after a useful reply and records its next step before waiting. Native goals and delivery handle continuation where supported. Instructions alone cannot guarantee that two idle, interrupted or exited clients will wake themselves.

What remains true

Keep the real constraints visible.

Connection still needs a receiver.

Native IDs and one-sided Codex setup are implemented. Use codex:UUID for an unregistered Codex target; its first eligible message read binds the connection. A dormant Claude receiver requires explicit activation. Actual cloud routing remains outside this local version.

Permissions stay with the client.

Automatic cross-agent approval is out of this version. An “approved” message cannot resolve a native tool prompt. A future approval feature would need a real, explicitly authorized hook adapter.

Durability stays in the transport.

Messages, deduplication, expiry, receipts and exact recipient checks remain. A submission does not prove the model read or completed a request.

Multiple connections already fit.

The local implementation supports multiple peers of either provider and disconnects one edge at a time. Isolated checks exercise this behavior. Native multi-session acceptance needs its own observed exchange.

Implementation and acceptance

Six methods built.
Validate the real exchange.

  1. Six-method facade — implemented.

    Attach/pair and receipt plumbing sit behind the facade. The store now preserves native identity across receiver restarts, and Claude receives through its durable inbox watcher. Legacy CLI controls keep exceptional recovery available.

  2. Native addresses and one-line status — implemented.

    Fresh native identity, explicit receiver activation, a silent connection, receiver availability and timestamped self-status. Native IDs work across multiple connected peers.

  3. Native-session acceptance — record the evidence.

    Connect, list, request a review, continue work, receive feedback and resume. Repeat with multiple peers, a busy recipient and stale status. Track observations in the live validation record.

Implemented: six default MCP methods, native session addressing, explicit Claude Monitor activation, fresh per-call context and self-status. Automated checks exercise subprocess restart, offline delivery and stdout failure. A native v0.3 Claude/Codex roundtrip is confirmed; busy and restarted native clients remain unverified; a queue submission alone is not a completed collaboration journey.
